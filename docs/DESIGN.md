# 教材UIの設計

## Overview

`SPEC.md`と承認済みのPhase 1設計に従う。情報セキュリティマネジメント合格程度の日本語話者が、PCを中心にスマートフォンでも技術基礎を学ぶ。落ち着いた学習ノートと操作パネルを組み合わせ、操作・重み・結果を結び付ける。販促的なヒーローや過度な装飾を加えない。

## Colors

実行時の値の正本は`css/common.css`の`:root`。ライトは白い教材面と淡い青灰色の背景、ダークは青灰色の暗い背景と明るい文字を使う。ダークの上書きは`:root[data-theme="dark"]`で一元管理する。操作、完了、入力エラーの意味は両モードで揃える。色だけで状態を伝えず、数値・ラベル・記号を併記する。各ページで独自の色を定義しない。

初回は端末の配色設定に合わせ、ヘッダーのダークモード切替で選んだ設定を`riss.a1.theme`に保存する。学習進捗とは別のキーで管理する。本文描画前に`js/theme.js`を実行し、保存した配色を適用する。保存不可でも切替でき、その旨を表示する。

## Typography

日本語本文は`--font-body`でメイリオを優先し、ヒラギノ角ゴシック、Noto Sans JPへフォールバックする。数値・進数・式は`--font-number`でConsolasなどの等幅フォントを使う。本文17px、行間1.8を基本にする。外部フォントを読み込まない。説明はです・ます調、操作は「反映する」「答え合わせ」「学習完了にする」で統一する。

## Layout

最大幅1120px。PCのトップは導入と進捗、2列の章カード。教材はページ内目次と本文。960px以下で目次を上部へ、760px以下でトップを1列へ。bit列は460px以下で上位・下位の4bitずつに分ける。スクロールは文書全体が管理する。

## Elevation & Depth

静的なカードは影を使わず境界線で区切る。Labは青い枠と結果領域で本文から区別する。

## Shapes

パネルは`--radius`、入力とbitは6px、通常ボタンは8px。主要操作は高さ48px以上、bitボタンは56px以上。

## Components

- `common.css`：共通トークン、操作、状態、フォーム、章カード、進捗。
- `lesson.css`：本文、問題、完了操作、前後ナビ。
- `lab.css`：Labの操作領域、重み、結果、レスポンシブ配置。
- 入力する進数はネイティブselect。OSのポップアップと標準のキーボード操作を使用する。
- 教材ID・順序・公開状態は`js/curriculum.js`。本文・目次のリンクは静的HTML。教材追加時は両方を更新する。IDは並び順で採番するため、教材は末尾にだけ追加する。本編より難しい内容は最後の「Extra」章に置き、目次の番号は`E01`、見出しは「Extra 01」と表示する（IDは30から）。トップの進捗はExtraを含む公開済みページ数で数える。
- 進捗は`js/progress.js`。形式バージョン1、サイト固有キー、完了と成績を分離する。破損・未知の形式は上書きせずメモリ内で継続する。
- 教材の構成はLesson 01を型とし、学習目標、まずイメージを掴む、なぜこの仕組みなのか、仕組みを理解する、触ってみる、試験ではこう問われる、学習を振り返るの順に置く。「なぜ」の節では、仕組みを覚える前に、その仕組みを選ぶ理由を示す。学習を振り返るは、試験対策として覚えておく用語（`term-list`）と、できるようにすることを端的に並べる。確認問題は置かず、過去問演習は教材外で行う。旧構成のページは順次移行する。技術の移り変わり（使われた理由・使われなくなった理由）は、本文に`aside.example.column`のコラムとして入れる。本文は興味を持ってもらうことを優先し、短く書く。「へー、そうなんだ」と思える身近な例を選び、網羅性や細部の正確さより読みやすさを取る。手順の詳しい説明や表は最小限にする。
- 確認問題は`js/quiz.js`（旧構成のページのみ）。各問の最初の回答を固定し、全問回答後に直近成績を保存する。再挑戦は成績や完了を直ちに消さない。
- Lab固有の状態・計算は`js/labs/`。入力値全体を検証してから結果を更新する。
- 進数Labは8bitのボタンと、進数を選んで反映するフォームで構成する。Lab前に確かめること・進め方を示し、10進数を自分でbitに直してから反映で答え合わせする流れにする。入力欄のラベルと例は選んだ進数に合わせ、2進数は8桁・16進数は2桁にそろえて表示する。形式は合っていて255を超える入力には、どの進数でも範囲の案内を出す。固有CSSは`number-system.css`に限定し、Lab本体を1440×860程度の画面に収める。
- 論理演算・半加算器・Dフリップフロップの動く図はインラインSVG。配線は実線=1、破線=0とし、数値ラベルと文章も必ず併記する。操作にはネイティブHTMLボタンを使う。論理演算の種類もselectではなく、押した状態（aria-pressed）を示すボタンで選ぶ。論理演算Labは760px以上で、操作と図を左、結果と真理値表を右の2列に置き、1440×860程度の画面に収める。Lab 2（`nand-combo.js`）はNANDだけでつないだ4つの回路（NOT・AND・OR・XOR相当）を選び、途中の線（N1など）の値も示す。真理値表のYは試した入力だけを表示し、全部試すと何の演算と同じかを示す。図はJSから状態を更新し、外部SVGのDOMアクセスやfetchに依存しない。
- 実物に近いハードウェア図はPNGで保存し、レジスタとキャッシュは同じCPU内部の拡大イメージとして示す。写真・リアルな絵にはSVG説明図用の色反転を適用せず、役割をHTMLの説明と代替テキストでも伝える。
- Lesson 02のSSD画像（`ssd-nand-flash.png`）は、`hardware-memory-components.png`のSSD部分を切り出し、引き出し線を背景色で消したもの。
- 画像・アイコン素材は`assets/images/`・`assets/icons/`へ保存する。説明用回路図はSVG画像とし、ラスタ画像が適切な場合のみPNGを使う。
- 論理回路の教材（Lesson 03）は、半加算器LabとフリップフロップLabの2つ。半加算器LabはXORとANDの図で1+1の桁上がりを示す。フリップフロップLabは、教科書と同じNORゲート2個の出力を交差させた図で、S（セット）・R（リセット）をLab 1と同じく0/1のボタンで切り替える。操作の記録（新しい順に5件）で、S=0・R=0なのにQが1のときも0のときもある＝今の入力だけで出力が決まらないことを示す。S=R=1は「禁止」と説明だけ示し、不定の扱いやClockのタイミングは扱わない。Lab 3（おまけ、`register.js`）は、D型のフリップフロップを4個並べた4bitレジスタ。重み8・4・2・1の「入ってくる値」（計算回路などから届く信号で、別のレジスタではない）をボタンで作り、「書き込む」の合図で4個が同時に取り込む。合図の後に入ってくる値が変わっても、覚えている値（10進数も表示）は変わらないことを示す。固有CSSは`flipflop.css`に限定する。

- CPU LabはLOAD・ADD・STORE・HALTの固定プログラムを手動で進める。取出し・解読・実行は教育用の段階で、実CPUのクロック数や命令長を再現しない。PC・IR・ACCと主記憶の値をSVG・表・文章で併記し、入力の反映時に実験を初期化する。CPU Labの主表示は日本語の指示とし、命令名は補足で対応を示す。番地は「場所」、値は「中身の数」と明記し、命令オペランドに裸の数字を表示しない。CPU固有CSSは`cpu.css`に限定する。CPU図のレジスタは横並びにし、図・主記憶・結果・操作を1920×900の表示領域で見渡せる配置にする。数値変更はネイティブdetailsに格納し、進め方はLab前の「このLabで確かめること」に置く。結果欄は高さを確保して段階操作時のボタン移動を抑える。狭い画面では縦並びと文書スクロールに戻す。

- キャッシュLabは3つの固定番地を2枠の完全連想キャッシュへコピーする読出しモデル。置換はLRUで、ヒット時も使用順を更新する。確認1単位・ミス時追加9単位・キャッシュなし9単位の教育用時間を明記する。元の主記憶は変更せず、場所と数を図・表・文章で区別する。平均と割合は読出し回数から計算し、未読状態は割り算しない。共通のLabに`memory-cache.css`を追加し、動く図はインラインSVGとする。

- 割込みLabは「ポーリング（確認だけ繰り返す）」「ポーリング（3単位ごとに確認）」「割込み」の3行を同じ時間軸に並べ、「1単位進める」で同時に進める。キーは学習者が「キーを押す」ボタンで任意の時点に押し、全行が受け取るまで次のキーは押せない。比べるのは各行の「進んだ計算」と「押してから受け取るまでの単位数」で、合計時間の勝ち負けにはしない。3行とも同じ1台のCPUであることを明記し、確認だけを繰り返す行は極端な例として扱う。ポーリングが他の仕事を一切できないという誤解を避けるため、確認の間隔による無駄と遅れのトレードオフを示す。Lab前に確かめること・目標・各方式の前提を示す。割込みの退避・受取・復帰は1枠にまとめ、退避の詳細は本文の図に任せる。時間は教育用の目盛りで、実機の比率は本文の速度表で示す。時間割は12単位までで、作業名の文字と枠線の種類を併記したインラインSVGとし、狭い画面ではキーボードで横スクロールできる領域にする。各行の集計（進んだ計算・受け取るまで）は時間割の右端に表示し、手順はLab前の説明に置いて、Lab本体を1440×860程度の画面に収める。selectは使わずネイティブボタン3つで操作する。固有CSSは`interrupt.css`に限定する。

- 浮動小数点数Lab（Extra 01）は、小数点の右8bitの固定小数点で0.1に近い値を作る。値は1/256単位の整数で持ち、表示する小数と0.1との差は整数計算から作り、JavaScriptの小数計算の誤差を表示に混ぜない。使うbit数は4bit・8bitのボタンで切り替え、4bitでは小数第5〜8位を0にして無効にする。「一番近い並びを見る」で答え合わせする。浮動小数点数の構成と誤差の種類は本文の表で扱い、Labには入れない。固有CSSは`floating-point.css`に限定する。

## Do's and Don'ts

- 見出し、入力ラベル、キーボード操作、可視フォーカス、読み上げ用状態を保つ。
- 実在するページだけリンクにする。準備中と未学習を区別する。
- 本文をJSやfetchに依存させず、通常のdeferスクリプトと相対パスを使う。
- 初期段階ではビルド、フレームワーク、汎用Labエンジンを導入しない。
- 確認問題の合格やスクロール到達を学習完了の条件にしない。
- JavaScript無効時には操作ボタンを表示せず、本文と静的なLabの例を残す。
